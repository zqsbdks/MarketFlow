# 自动补货建议与保底库存

2026-10-04：订货计划增加自动填写数量及“保底库存”列，位置为七天日期列右侧、可售库存前。

## 计算与人工优先

保底库存默认0，可按门店供应商品设置。用户确认含义是“预计库存至少保留该数量”，库存足够时不下单，并非每天至少订该数量。

建议量 = max(0, 当日预计销量 + 保底库存 − 当日预计可用库存)。预计可用库存包含已有到货单与更早的计划到货。

最近28个完整日期中同星期几的销量合计除以4，向上取整，作为该星期几的预测；当天剩余销售需求按09:00–21:00剩余营业时长折算。模拟逐日移除过期批次、加入已订到货并按先到期先出扣减预测销售，每日只补一天的需求，避免相邻日期重复补货。新商品无历史销量时预测0，可用保底库存启动补货。

这是按日期和预测销量估算的库存，实际销量、到货延误或破损可能产生差异。按日推演将当天预计到货计入当天可用量，不保证到货前每个小时都有库存。人工大额订货和保底设置以员工输入为准。

旧人工填写量保留在purchase_plan.quantities，包括0；新增automatic_quantities单独存放系统建议。系统刷新不会修改人工量。前端显示人工调整/自动建议，人工格子提供“恢复自动建议”，以quantity:null删除该格人工覆盖，重新计算。

## 后台与接口

后台启动以及每小时刷新所有启用门店、部门的七天自动计划，无需浏览器保持打开。每天12点刷新截止日最终快照后，由已有后台任务自动提交。已生成进货单或已锁定的自动快照不被后续刷新覆盖。只有正数明细生成订单，重复执行仍保持幂等。系统可以使用本店有效店长/正式员工做订单归属记录；员工尚未修改初始密码不阻止系统任务，但仍不能绕过登录后的改密要求操作前端。

PUT /purchases/minimum-stock 保存保底库存，与计划写入采用相同门店、角色和部门权限，并写审计。PUT /purchases/planning 的quantity允许null，表示恢复自动。GET /purchases/planning 返回minimum_stock、suggested_quantity、forecast_sales、is_manual及有效planned_quantity。
