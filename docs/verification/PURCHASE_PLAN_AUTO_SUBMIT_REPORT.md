# 每日截止后自动生成进货单

2026-10-04：进货管理中的“新建进货单”改为“订货计划”，移除手动提交按钮。

## 使用规则

- 日期列表示到货日期；输入的是该门店、部门、商品在该日的计划订货总量。
- 输入后自动保存到服务器，关闭页面再打开仍保留。15改成25是覆盖为25，不累计为40。
- 填零取消该商品。未填写数量的商品不订货，全为零的计划不生成空单。
- 日本时间每天12:00截止两天后的到货日；例如10月4日12:00锁定10月6日的计划。后端同时禁止修改，不能绕过灰色输入框。
- 后台整分钟检查到期计划，在12:00生成；失败会在后续分钟重试，应用启动时补处理停机期间已截止的计划。
- 每个门店、部门、到货日只有一个计划；正数明细合成一张进货单。生成、记录关联单号和系统审计在同一事务中，重复执行不重复生成。
- 生成后沿用既有签收和批次入库流程。生成进货单本身不增加库存。
- 此次实现保存人工填写的计划及定时提交；蓝色上周销量仍为参考，并未自动推算订货数量。
- 自动任务要求后端运行且启用 APP_RUN_SCHEDULER；关闭浏览器不影响服务器上的任务，电脑/服务停机后在重启时补处理。

## 接口与数据

GET /api/v1/purchases/planning：每日明细增加 planned_quantity。

PUT /api/v1/purchases/planning：单格保存（部门、到货日、供应商品ID、数量）。本店店长或该部门正式员工可写；总部、契约员工、跨店写入禁止。保存前验证目录所属店铺、部门和启用状态；数量为0到1,000,000的整数。

旧 POST /api/v1/purchases/ 及AI直接创建订单操作返回409，避免截止前绕过计划提前下单。内部历史创建服务保留供兼容及回归使用。

迁移 c453fbf6a0a7（前置428315d374cd）只新增 purchase_plan 表，已应用本地。采用门店/部门/到货日唯一约束、原子创建计划及行锁协调保存和自动提交。停机补单仍以原截止时间为下单时间。
