# 销量预测与历史经营报表缓存

2026-10-04：继续使用装饰器集中管理缓存，增加纯查询结果缓存，不缓存数据库会话或写入操作。

| 数据 | 策略 |
| --- | --- |
| 最近28个完整日期的同星期销量预测 | 缓存24小时，键包含日本业务日期、门店和商品集合；跨日期重新计算 |
| 营业概览、部门对比、排行榜、经营分析的销售汇总 | 仅查询结束日期早于今天时缓存3分钟；包含今天或未指定结束日期时实时查询 |
| 库存批次、待到货单、人工订货量、保底库存 | 实时读取，每次重新推演最终补货量 |
| 废弃损耗汇总、账号状态及权限验证 | 实时查询 |

缓存键还包含函数名、数据库标识及报表查询权限范围，避免不同门店或查询条件混用结果。金额、时间和元组通过类型化序列化恢复，保持原接口结果类型。权限校验在查询装饰器之外，每次请求仍执行，命中缓存不能让停用账号继续访问。

Web应用和独立后台调度器使用同一初始化方法。配置Redis时可跨进程共享预测；未配置Redis或启动连接失败时回退到进程内缓存，各进程分别复用。读写缓存失败时回退到数据库，不影响订货业务。

历史数据导入或修改不在普通销售接口范围内；维护历史数据后应清理`sales-forecast-v1`、`historical-reports-v1`命名空间，或等待过期。普通当日销售不会改变预测所使用的前28个完整日期，因此无需每笔销售清空预测缓存。无需数据库迁移。
