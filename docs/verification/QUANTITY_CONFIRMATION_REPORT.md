# 订货数量与保底库存异常确认

2026-10-04：输入框结束编辑（失去焦点或回车）后发起检查。正常数量自动保存；异常数量显示商品、到货日期、数量、参考量、原数量及原因，选择返回修改或确认使用此数量。返回修改恢复已保存值并聚焦输入框；填写0仍取消订货，恢复自动建议不需要人工确认。

检查依据：订货量参考实时建议量、预测日销量和保底库存；保底库存参考近期同星期预测销量和原保底值。

- 数量至少50且达到参考量5倍时，提醒明显超过需求；无销量参考时50起提醒。
- 原数量大于0且新数量恰为原数量10倍，提醒可能多输入一个0。
- 两位及以上全部相同的数字（11、22、33、44、99、111等）均提醒可能重复按键，不再依据参考销量过滤。
- 正常高销量商品不会仅因填写500而弹窗；重复数字按上述独立规则确认。数量与已保存值相同时无需再次确认。
- 输入只接受0至1000000之间的整数。

后端执行同样检查。首次异常请求返回`confirmation_required: true`、`saved: false`及签名凭据，并不写入数量。客户端不能把HTTP成功状态当作已经保存。确认后携带`confirmation_token`重新请求；凭据有效期10分钟，绑定员工、门店、操作类型、部门、商品、到货日期和填写数量，不能用于其他数量或操作。后端仍重新验证权限和截止时间。确认原因及参考量保存到现有操作审计记录，无需迁移数据库。

保底库存未经确认保持原值；订货量未经确认保持原计划，因此中午自动生成订单只使用已保存的值。系统自动建议不逐项弹窗。新增提示覆盖中文、日文、英文。

验证：后端267项通过，7项可选MySQL测试跳过；前端34项通过；构建、Ruff、Mypy通过。新增测试覆盖输入中不保存、500确认保存、99返回修改、保底确认、正常高销量不误报、签名绑定与过期、截止后拒绝、审计记录以及未确认异常不进入中午订单。
