## 使用入口与统计口径

经营分析 → 废弃损耗分析。选择起止日期和部门，点击生成分析。
总部可勾选“全公司汇总”，查看按成本降序排列的门店对比；普通员工没有全公司选项。
显示废弃成本、数量、记录数，以及原因、部门、门店的成本占比和对比条。
金额来自废弃单的批次进货成本快照，不重复加总批次明细。
比例分母为当前筛选总损耗成本，保留两位小数，合计可能有舍入差异。
起止日期均包含当天，按日本时间完整日期统计，包含凌晨自动废弃；最多查询367天。
废弃损耗单独展示，现有销售毛利润定义不变。

新增只读接口：`GET /api/v1/reports/discard-analysis`，参数 `start_date`、`end_date`、可选 `department_id`。
总部使用 `X-Store-ID: all`；经过现有账号状态、初始密码及门店隔离检查。
一个分组查询生成所有结果，保证各项金额来自同一数据快照。无需结构迁移。

## 员工资料规则

- 创建账号需要姓名、角色和相应归属，创建后提示补齐员工详情。
- 完整档案需要出生日期、入职日期、电话、地址和雇佣状态；性别允许未填写。
- 电话、地址不能为空或仅含空格。出生日期不能晚于今天或入职日期，入职日期不能在未来。
- 离职字段只适用于离职或解雇；原有日期先后与权限校验保留。
- 详情显示“档案完整 / 档案待补齐”。

执行 `python -m scripts.complete_demo_employee_profiles`，补齐272个模拟账号中的262份缺失资料。
仅填空项，保留身份、密码、权限和已填写资料。新增地址标明虚构，电话仅用于演示。
生成出生日期保证入职时成年。修改前备份保存在本机 `.cache/employee-profile-backup-*.json`。
