# 废弃损耗分析与员工资料完善

验收日期：2026-10-04（日本时间）。

## 使用入口与统计口径

经营分析的“选择查询指标”中直接勾选损耗金额、损耗占营业额比例、废弃数量、废弃记录数、废弃原因占比、部门损耗对比，以及总部可选的门店损耗对比。选择起止时间和部门，点击生成分析；未勾选的指标不返回、不展示。
新增“损耗占营业额比例”：损耗成本除以所选销售时间范围的营业额，无营业额时显示横线。
销售按原有起止时刻计算，废弃按同一范围的完整日期计算，包含凌晨自动废弃。
总部可勾选“全公司汇总”，查看按成本降序排列的门店对比；普通员工没有全公司选项。
显示废弃成本、数量、记录数，以及原因、部门、门店的成本占比和对比条。
金额来自废弃单的批次进货成本快照，不重复加总批次明细。
比例分母为当前筛选总损耗成本，保留两位小数，合计可能有舍入差异。
废弃按同一时间范围对应的完整日期统计，起止日期均包含当天，包含凌晨自动废弃；经营分析遵循原有查询范围，兼容独立接口仍限制367天。
废弃损耗单独展示，现有销售毛利润定义不变。

前端统一调用原有 `GET /api/v1/reports/analytics`，`metrics` 新增 `loss_cost`、`loss_revenue_ratio`、`discard_quantity`、`discard_count`、`discard_reason_share`、`department_loss_comparison`、`store_loss_comparison`。原独立只读接口保留兼容，前端不再调用。
未勾选损耗指标时不查询废弃表；仅选择金额或数量时不查询分类明细；仅选比例时内部查询营业额，但不额外返回未勾选营业额。零营业额返回null。
总部使用 `X-Store-ID: all`；经过现有账号状态、初始密码及门店隔离检查。
一个分组查询生成所有结果，保证各项金额来自同一数据快照。无需结构迁移。

## 员工资料规则

- 创建账号需要姓名、角色和相应归属，创建后提示补齐员工详情。
- 完整档案需要出生日期、入职日期、电话、地址和雇佣状态；性别允许未填写。
- 电话、地址不能为空或仅含空格。出生日期不能晚于今天或入职日期，入职日期不能在未来。
- 离职字段只适用于离职或解雇；原有日期先后与权限校验保留。
- 详情显示“档案完整 / 档案待补齐”。

生成出生日期保证入职时成年。修改前备份保存在本机 `.cache/employee-profile-backup-*.json`。
